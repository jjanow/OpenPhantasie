# Phantasie III (DOS `MAIN.EXE`): function map (3c.5)

Phase 09 T4, task 3c.5 (s79, static). Generated by `tools/scripts/fmap_p3.py --write` (re-run after changing the
hand labels in its `NAMES` table; the tables after the TABLE marker below are overwritten). Formats and record
fields: `FORMAT.md`; behaviour: `logic-specs/`.

**Addresses.** `root` = offset in the unpacked root image (`FORMAT.md` §1, "img"); `ovlN` = offset in overlay N's
load image (resident at img `0x13d50`, so img = `0x13d50 + addr`). Far calls in root code are `seg:off` with
img = `seg·16 + off`. Amiga = offset in the flat `PhantasieIII` image (`extract_amiga_p3_common.load_flat()`;
CODE hunk at 0, DATA at `0x21890`).

**Method.** Function starts = MS C prologues (`push bp; mov bp,sp`) + relocated far-call targets + `push cs;
call` targets + near-call targets that start with `push bp`; a function runs to the next start (MS C emits
contiguous bodies). For each function the script lists: master string-table refs `S<k>` (`es:[0x1308 + 4k]`;
`/idx` = indexed, i.e. a name table such as item names `S150 + id`, so the shown text is only the table base),
DGROUP literal strings `DS:x` (`/lit`), message-box calls (`/msg`: helpers `0x8bd8`, `0x929a`, `0x999f`, `0x9bfd`
show string `389 + n`), master tables (item points / requirement / value, town price index, hit-location odds
`DS:0x12cc`), monster data (`FAR:0xfd1e`) and fields of the 262-B record, wherever it is addressed: the work copy
`FAR:0x9de8`, the party (`FAR:0x236 + 0x106·i`, 7 slots) or the roster (`FAR:0xe820 + 0x106·i`, 20 slots).
"Master table" covers the item tables, the hit-location table and the monster data; the spell table (`DS:0x1208`)
and the I → III class / race maps (`DS:0x48`, `0x4e`) are not scanned (their small displacements matched record
field offsets and gave false hits); their users are the transfer (ovl1 `0x00a5`) and the spell routines.
Boundaries are `[~]` where a function has no prologue (a few near helpers are merged into the function before them).

**Amiga pairing.** The Amiga program is Aztec C with absolute (relocated) addressing; strings sit in the CODE hunk
and in a 400-entry pointer table at `0x22a14` (DATA). A DOS function is paired with the Amiga function that shares
the most normalised strings (rare strings weigh more). Only 68 of 786 Amiga functions reference text directly
(most messages go through the pointer table by computed index), so pairs exist only for the text-heavy routines.
"Amiga (n)" = start of the Amiga function, n = shared strings. Pairs with n = 1 are `[~]`.

**Not covered:** the MS C runtime (`img 0x3b20–0x6f60`, counted only) and the MSEM87 float emulator
(`img 0x118f0+`). Unlabelled = no string, table or record reference and no hand label; they are counted per module.
