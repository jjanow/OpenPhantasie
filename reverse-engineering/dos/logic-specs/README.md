# Phantasie I (DOS) — Logic Specifications

Behavioral specs for the SSI 1987 IBM/DOS release of *Phantasie*, produced in
Phase 3. These describe **what each subsystem does**, in plain English +
pseudocode, precisely enough that the Phase 6 C# implementation is a translation
exercise. They are *not* line-by-line transliterations of 8086 assembly.

## Source material (in priority order)

1. **The binaries/data files** — `../original-files/` — the source of truth.
2. **Ghidra static analysis** — `../ghidra/` (function maps, string tables, and
   `*.decompiled.c` decompilation of `PHANTASI.COM`, `OV1.OVR`, `OV2.OVR`).
3. **Extracted data** — `../extracted/*.json` (regenerated by `tools/scripts/`).
4. **Corroborating references** — the SSI game manual and Andrew Schultz /
   hitchhikerprod community walkthroughs. Used to *cross-check* values found in
   the binary, never as a primary source.

Dynamic verification under DOSBox (plan §3.2) was **partial** — guild /
inventory / XP / prices / skills / mystic score verified by save diffs +
screenshots; combat formulas are static-[C]. Remaining open items are listed
below and carried into Phases 5–6.

## Confidence legend

Every non-obvious claim is tagged:

- **[C]** Confirmed — read directly from the binary/data or decompilation.
- **[X]** Cross-checked — binary finding corroborated by manual/walkthrough.
- **[I]** Inferred — deduced from structure/strings but not yet code-verified.
- **[?]** Open — needs a dynamic run or deeper static work; noted as such.

## The game's file/executable layout

| File(s) | Role |
|---|---|
| `PHANTASI.COM` | Main program + master data tables (names, items, spells, monsters, char-sheet format). Loaded flat; not MZ. |
| `OV1.OVR` | Overlay: town / guild / character-management / shop logic. |
| `OV2.OVR` | Overlay: combat + dungeon logic. |
| `R32768.COM`, `M1.COM`, `M2.COM`, `MONO.COM` | Tiny TSRs used as the home-grown overlay/memory manager (allocate RAM, stash pointers in IVT slots 0x60–0x63). Not game logic. |
| `OUT1..OUT19.DAT` | Overworld regions (32-col tile grids + embedded location text). |
| `DNG1..DNG10` | Dungeon levels (feature grid + embedded event text). |
| `TWNS.INT`, `TWNS.DAT` | Town interior maps + names; per-town state. |
| `MESS1..MESS10` | Encrypted event/message text (cipher cracked — see `message-and-text.md` → `extracted/messages.json`). |
| `SCROLLS.DTX` | Encrypted scroll text. |
| `GUILD.DAT` | Adventurers' Guild roster (the closest thing to a save; see `save-file-format.md`). |
| `SACK.DAT`, `DNG.SAV`, `DNGX.SAV` | Loot sack + dungeon/party save state. |
| `MSTR1IBM.PAT`, `MSTR2IBM.PAT`, `PRT1IBM.PAT`, `PRT2IBM.PAT`, `PAT`, `*.IBM` | CGA graphics (2 bits/pixel). `PAT` = overworld map tiles (`map-tile-graphics.md`). |
| `FONT` | Bitmap font. `PHM` | PC-speaker music/sound tables. |

## Regenerating the extracted data

```bash
cd tools/scripts
python3 extract_names.py   # -> extracted/names.json
python3 extract_maps.py    # -> extracted/overworld.json, dungeons.json
```

Ghidra re-analysis + exports:

```bash
cd reverse-engineering/dos
snap run ghidra.analyzeHeadless ghidra PhantasieDOS \
  -import original-files/PHANTASI.COM original-files/OV1.OVR original-files/OV2.OVR \
  -processor "x86:LE:16:Real Mode"
# then, against the saved project:
snap run ghidra.analyzeHeadless ghidra PhantasieDOS -process -noanalysis \
  -scriptPath ../../tools/scripts -postScript GhidraExport.java $PWD/ghidra
```
